AI Agents and Agent Architecture 13 lessons · voice A

Design agents you can trust: the loop, tools and protocols, memory, patterns for planning and composition, and the controls for permissions, injection, traces, evaluation and oversight.

A developer who has called a language model from code. ai-engineering (tokens, prompts, retrieval, evaluation) is the recommended earlier course. Coding assistants are covered separately in ai-assisted-engineering. Prerequisites: python-for-data-analysis, cs-basics, probability-statistics, ai-engineering.

Outcomes

  • You'll be able to choose between a workflow, a copilot and an agent for a task.
  • You'll be able to trace an agent loop and compute its cost and reliability.
  • You'll be able to design tools and a server-side permission model.
  • You'll be able to recognise prompt injection and break the lethal trifecta.
  • You'll be able to instrument and evaluate an agent and stage its rollout.

AI-Assisted Engineering and Code Review 12 lessons · voice A

Work with coding assistants as an engineer who owns the result: instructions and context, specs and tests first, small steps, reading and securing machine-written changes, and measuring the effect.

A developer who can read Python and SQL and use git. The ai-engineering and ai-agents courses explain how models and agents work; this one is about using them and reviewing their output. Prerequisites: cs-basics, python-for-data-analysis, sql-from-rows-to-reports, git-and-version-control, software-testing-and-quality.

Outcomes

  • You'll be able to write a specification and tests that an assistant's change must satisfy.
  • You'll be able to read a diff against its intent and find unrequested changes.
  • You'll be able to spot typical machine-made defects and security faults.
  • You'll be able to separate an assistant's claim from evidence.
  • You'll be able to write working rules and measure whether assistance helps.

  2. Context and instruction files. Decide what to put in an assistant's context, write a project instruction file, and estimate whether a codebase fits in the window.
    Figures: svg_figure (A window bar with repo size laid beside it.); table (Candidate instruction lines.)
  3. Specification first. Write a specification with testable acceptance criteria before asking an assistant to build.

    Figures: program_trace (The function and test run line by line with the result of each assert.); table (Mutants and whether each was killed.)
  5. Small steps and version control. Split a large change into reviewable commits and use version control to checkpoint and undo.
    Figures: svg_figure (A commit graph with a checkpoint and a revert commit.); table (Three task descriptions sized in lines.)

    Figures: svg_figure (A diff with hunks coloured by whether the spec mentions them.); table (Review order checklist.)

    Figures: relational_query (A users table and the query result for a normal and a hostile name.); table (Four endpoints with owner checks.)

Evidence and professional practice

  1. Verifying behaviour. Gather evidence that a change works, and distinguish an assistant's claim from an observed result.

AI Engineering: LLMs, Prompting, Retrieval and Evaluation 13 lessons · voice A

Build and judge applications on top of language models: tokens and cost, prompts and structured output, embeddings and retrieval, evaluation, security and operation.

A developer or analyst who can write Python and read a statistical result. Machine-learning metrics (precision, recall) help; machine-learning-and-mlops is the recommended earlier course. Agents and coding assistants come in later courses. Prerequisites: python-for-data-analysis, probability-statistics, cs-basics, linear-algebra-vectors-and-maps, machine-learning-and-mlops.

Outcomes

  • You'll be able to estimate the tokens, cost and latency of a model call.
  • You'll be able to write a prompt as a testable specification.
  • You'll be able to build and score a retrieval pipeline.
  • You'll be able to design an evaluation set and read its noise honestly.
  • You'll be able to name the main security failures of LLM applications and their controls.

Working with a language model

  1. Tokens and the context window. Estimate the tokens and cost of a request and work out how much room a prompt leaves for the answer.
    Figures: svg_figure (A sentence broken into coloured token chips with a running count.); svg_figure (A bar of the context window split into system, history, question and room for the answer.)
  2. How a language model chooses the next token. Convert logits to probabilities with softmax, and predict the effect of temperature and top-p on sampling.
    Figures: graph_plot (A bar chart of next-token probabilities for demonstration logits (1.5, 1, 0.5), not the 2, 1, 0 in the questions.); table (Cumulative probability by token for top-p.)
  3. Prompts as specifications. Write a prompt with an instruction, constraints and examples, and judge two prompt versions on a test set instead of a single demo.
    Figures: table (A prompt version column and pass/fail marks across 20 test cases.); svg_figure (Prompt parts as stacked labelled blocks.)
  4. Structured output and tool calls. Validate a model's JSON against a schema, retry safely, and explain the tool-call round trip.
    Figures: svg_figure (A sequence diagram: user, app, model, tool.); python_execution (A small validation function the learner runs on good and bad strings.)

Quality, safety and operation

  1. Evaluation sets and statistical noise. Build an evaluation set with the cases that matter and say how much a small set can tell you.

    Figures: table (A 2×2 agreement table of judge versus human.); svg_figure (Two answers shown in either order with a judge's picks.)

    Figures: table (Per-case before/after with flipped rows highlighted.); svg_figure (A deploy pipeline with the gate between build and release.)

Analytics Engineering and Data Governance 14 lessons · voice A

How raw data becomes trusted analysis: dimensional models, transformation layers, tests and metrics, then lineage, quality, privacy and the roles that govern all of it.

A capable adult who can write SQL joins and aggregates (sql-from-rows-to-reports) and has seen a data pipeline (data-engineering helps but is not required). No previous modelling or governance knowledge assumed. Tools such as dbt are named only as examples. Prerequisites: sql-from-rows-to-reports, data-engineering.

Outcomes

  • You'll be able to declare a grain and design a star schema around it.
  • You'll be able to keep history in dimensions and avoid fan-out in joins.
  • You'll be able to place logic in layers, write data tests and define metrics once.
  • You'll be able to trace lineage, measure quality and read a contract and a service level.
  • You'll be able to classify and protect personal data and explain what governance has to do in practice.

A capable adult with no medical training who wants to know what a first aider does and why, before or alongside a hands-on course. They need only everyday knowledge of the body. Nothing here qualifies the learner to give first aid in a workplace or to hold a certificate.
