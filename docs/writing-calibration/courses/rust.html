Both lessons written from the curriculum by Sonnet in voice A, screen by screen as you will meet them. Code questions, cases and projects are unchanged.

About this course

Rust is a systems programming language whose compiler examines a program far more thoroughly than most before it will let the program run, and a beginner meets that compiler early and often. This course treats it as a teacher: the programs are short, you say what each one does before running it, and when rustc refuses one, its message shows which rule was broken and usually how to mend it.

The first lesson covers how a program prints values, how a name is attached to a value with let, and why Rust keeps a name unchangeable unless it is declared with mut. The second covers whole and decimal number types, the rule that stops them being mixed by accident, and functions that take and return values of stated types. Every exercise that asks for code is compiled and run for real, and the same tools are open to you in the playground and in the Rust projects.

  • You'll be able to read a short Rust program and say what it prints.
  • You'll be able to name a value with let and decide whether it may change with mut.
  • You'll be able to choose between i32 and f64 and predict the result of dividing whole numbers.
  • You'll be able to write a function with typed parameters and a return type.

Teaching

A Rust program starts at fn main, and println! prints a line of text.

Every Rust program that you run begins at a function called fn main, whose body is the pair of braces that follows it. The lines inside are carried out in order from the top, and when the last one has finished the program ends, which is why the programs in this lesson share the same outer shape and differ only in what is written between the braces.

The line that produces output is println!, which prints its text and then starts a new line. The exclamation mark shows that println! is a macro and not an ordinary function, a difference that does not matter yet, and the text it prints is written between double quotation marks. Wherever the text contains a pair of braces, Rust fills the gap with one of the values listed after the text, taking the values in order, so that the first {} receives the first value, the second {} the second, and so on.

[Figure]

In the figure the three pairs of braces are filled by 6, 7 and 6 * 7. The last of these was never written out as a number, because Rust works out 6 * 7 before printing, so any calculation placed after the text is carried out first and its result is printed. Both the order of the values and this use of a calculation are needed in the next two exercises.

Teaching

let gives a value a name, and later lines can use the name in place of the value.

Writing 3 + 4 after the text is enough for a single sum, but a program soon needs the same value in several places, and repeating a number would mean changing every copy whenever the number changed. Rust avoids this by letting you attach a name to a value with let: the line let price = 4; creates the name price, gives it the value 4, and from that line onwards price can be written wherever 4 could.

A name can be defined from other names, because the right-hand side of a let is a calculation like any other. In the figure, cost is given the value price * quantity, which Rust works out when it reaches that line, and the final println! then prints all three names. Inside the braces of the text a name may be written directly, as in {cost}, and Rust fills the gap with the value that the name stands for.

[Figure]

Each line can use only names that were created above it, because the program is carried out from the top and a name that has not yet been created has no value to offer. That is why cost, which depends on price and quantity, comes after both of them. A name made in this way is called a variable, although, as the next screens show, in Rust it does not vary unless you ask it to.

Teaching

Writing mut after let allows a variable to be given a new value later.

The repair that rustc suggested is a single word. Writing the word mut, short for mutable, after let tells Rust at the moment a name is created that it will be given new values later, and with that permission an assignment such as lives = lives - 1 is accepted. The right-hand side is worked out first from the old value and the result then replaces it, so that after the assignment lives holds 2 and the 3 is gone.

Rust asks for the permission at the start, and not for the change at the moment it happens, for a reason that grows with the size of a program. When every name is unchangeable unless it is marked, a reader can see at once which names are able to change, and the ones without mut can be set aside when hunting for a value that has gone wrong. The cost to the writer is one word.

Teaching

A second let with the same name creates a new variable that hides the first.

A different value can also arrive under the same name without mut. If a program writes let amount = 4; and later let amount = amount * 3;, the second line is not an assignment to the first amount. It creates a new variable that happens to share the name, calculated from the old one, and from that line onwards the name refers to the new variable. This is called shadowing, because the new variable casts a shadow over the old one.

Since the second amount is a new variable, nothing obliges it to resemble the first. In the figure it holds the number 12 and then, after a third let, the text twelve, which no assignment to a single variable could do, because an assignment must keep the type of value the variable was created with (the next lesson explains types properly). Shadowing is therefore the tool for building a value in stages, while mut suits a value that is updated again and again in place, such as a counter.

[Figure]

Each let leaves the earlier variable unchanged and merely out of reach by name, whereas an assignment overwrites the one variable that exists. When it is unclear which of the two a line is, check whether the line begins with let.

Teaching

Rust has whole-number types and decimal types, and dividing one whole number by another gives a whole number.

Every value in a Rust program has a type, which says what kind of value it is and therefore what can be done with it. Numbers come in two families that are used constantly. The whole numbers, written with no decimal point, have types such as i32, a 32-bit integer that holds any whole number from about −2 billion to +2 billion, and the numbers with a decimal point have types such as f64, a 64-bit floating-point number. When you write a number and nothing else in the program says which type it has, Rust chooses i32 for a whole number and f64 for a number with a decimal point.

The distinction matters most for division. When both numbers are whole, the result is whole as well: Rust divides, discards the remainder and keeps the quotient, so 9 / 4 is 2 and not 2.25. Writing both numbers with a decimal point, as in 9.0 / 4.0, makes them f64 values, and the division keeps its fraction.

[Figure]

The figure prints both results side by side. The whole-number result is not 2.25 rounded: the remainder is simply dropped, so that 9 / 4 and 11 / 4 both give 2. A decimal point therefore changes the answer and not merely its appearance, because 9 and 9.0 are values of different types.

Teaching

The word as converts a value from one number type to another.

To combine a whole number with a decimal one, you convert one of them, and the word as does so: total as f64 takes the whole number held in total and produces the same number as an f64. The variable total is unchanged, since as makes a converted value and does not alter its source, and the new value can then be used in any calculation that needs an f64.

In the figure the whole number 9 is converted before the division, which is why the result keeps its fraction. The conversion belongs to total alone, because as binds more tightly than /: the line is read as (total as f64) / 2.0, a decimal divided by a decimal, and no mixing is left for the compiler to object to.

[Figure]

Conversion in the other direction is also possible, but it can lose something. Writing 9.7 as i32 gives 9, because the part after the decimal point is discarded and not rounded, whereas converting a whole number to f64 keeps its value. The word as marks the place in a program where you decide which of these you want.

Teaching

A function names a calculation, states the types it takes and returns, and gives back its last expression.

The programs so far have contained one function, main. You write others with the same word fn, followed by a name, a list of parameters in brackets, and an arrow and a return type before the braces. In fn double(n: i32) -> i32, the function double takes one parameter, n, which must be an i32, and the arrow says that it hands back an i32. Every parameter and the result have their types written out in this way, because Rust does not guess the types at the edges of a function.

The body is the code between the braces, and the value that the function returns is simply its last line, written without a semicolon. In the figure that line is n * 2, so double(21) is 42, and main stores the value in result before printing it. A function is called by writing its name with the values to use for its parameters, and each call runs the body again with the parameters set to those values.

[Figure]

The first line of a function can be read as a contract: it says what must be supplied and what will come back, and the compiler checks every call against it. A call that supplies an f64 to double, or that treats its result as text, is rejected before the program runs, which is the same strictness about types as on the earlier screens.
