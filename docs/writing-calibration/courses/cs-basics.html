About this course

A program is a list of instructions that a machine follows exactly, with no judgement of its own to fall back on, and computer science begins from that fact. So much of what a computer does, from keeping a contact list in order to finding a route, comes down to writing out steps precisely enough for such a machine and then asking how long those steps take, and this course takes up both halves of the problem.

The first three lessons deal with writing a procedure. They begin with lines that run one after another, go on to a line that makes a choice by testing a value, and then to steps that repeat for as long as a test allows, and in each case you follow small programs by hand, one line at a time. The last three lessons deal with how long a procedure takes. They take the job of finding one item in a list, compare two ways of doing it, and count the checks that each one makes as the list grows, until the counts show when it is worth sorting the list first.

You do not need to know a programming language, because the programs are a few lines of Python-style code and each lesson explains a line before it asks you to follow it.

  • You'll be able to follow a short program line by line and say what x holds at the end.
  • You'll be able to say which branch of an if/else runs, including when a value sits exactly on the edge of the test.
  • You'll be able to count how many times a loop runs and spot one that will never stop.
  • You'll be able to count the checks a linear search and a binary search make on a list.
  • You'll be able to say how the number of checks grows with the length of the list, and when a sorted list is worth having.

Teaching

An algorithm is a finite list of exact steps that ends with an answer.

The card in the opening worked because every line on it could be carried out without making a decision. “Add 4” leaves nothing to interpret, whereas an instruction such as “make it a bit bigger” does, because a person would have to choose how much bigger, and two people could choose differently and finish with different numbers. A machine cannot choose at all, so a procedure written for one has to be made of steps that each mean one thing.

A procedure that meets this standard is called an algorithm: a list of steps, each of them exact, that comes to an end and leaves an answer. The word is a Latin form of the name of al-Khwarizmi, a mathematician working in Baghdad in the ninth century, whose book on arithmetic with the Hindu-Arabic numerals reached Europe in Latin translation.

A new value replaces the old one

So far each line after the first has used the old value of x in its sum. That is common, and it is not required. A line such as x = 1 does not read x at all. It puts 1 in the box and throws away whatever was there.

Greater than, and greater than or equal to

The test in the picture used >, which means strictly greater than. It leaves out equality, so 5 > 5 is false, because 5 is not more than itself. Programs have a second symbol, >=, for greater than or equal to. It includes equality, so 5 >= 5 is true.

The two symbols agree on every value except the one on the edge. For x = 4 and x = 6, the tests x > 5 and x >= 5 give the same answers: false for 4 and true for 6. They split only at x = 5 itself. The matching pair for going down is < and <=, which behave the same way at their edge.

That single value is where mistakes cluster, so a careful programmer tries the edge value first. Try a program with the edge value in it.
